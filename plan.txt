1. EXECUTIVE OVERVIEW
--------------------------------------------------------------------------------
Sales-CRM is an enterprise-grade field force management and sales automation 
platform designed to streamline workforce attendance, track field activities, 
provide automated daily movement timelines, and manage daily task reporting 
under a secure Role-Based Access Control (RBAC) system.

Key Pillars:
- Multi-tier RBAC: Admin, Business Manager, Field Representative.
- Geofenced & Photo-Verified Attendance: Face selfie + GPS punch in/out.
- High-Efficiency Background Location Tracking: Battery-optimized route recording.
- Dwell Time / Stop Detection: Automatic timeline of visited places and wait times.
- Work Log & Review System: Field reporting linked with timeline check-ins.
- Comprehensive Admin Command Center: Live map, photo verification, timeline player.


2. RECOMMENDED TECH STACK & SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
A. Mobile Application (Field Rep & Business Manager):
   - Framework: React Native with Expo (SDK 51+)
   - Navigation: React Navigation (v6/v7) with Role-Based Route Guards
   - Camera & Media: Expo Camera / ImagePicker (Camera-only selfie validation)
   - Geolocation & Background Tasks:
     * expo-location (Foreground & Background location tracking)
     * expo-task-manager (Headless background worker for periodic GPS pings)
   - Local State & Caching: Zustand / Redux Toolkit + AsyncStorage
   - Maps & Polylines: react-native-maps (Google Maps / Apple Maps integration)
   - Network / Offline Sync: Axios with offline SQLite queue for low-network zones

B. Web Admin Dashboard (Admin & Management):
   - Framework: React.js (Vite) / Next.js
   - UI Library: TailwindCSS + Lucide Icons + Shadcn-style components
   - Interactive Maps: Leaflet.js / Mapbox GL / Google Maps React
   - Data Visualization & Charts: Recharts (Attendance trends, dwell times, hours)
   - Photo & Lightbox: React Photo Viewer for selfie audit

C. Backend API & Services:
   - Server Runtime: Node.js with Express.js / NestJS (or Python FastAPI)
   - Database: PostgreSQL (with PostGIS for high-performance spatial queries)
     * Alternative: MongoDB or SQLite for initial lightweight setup
   - ORM: Prisma ORM (Type-safe models and migrations)
   - Authentication: JWT (JSON Web Tokens) with refresh token rotation + Bcrypt
   - Storage for Photos: AWS S3 / Cloudinary / Supabase Storage (Selfie uploads)
   - Real-time Updates: Socket.io or WebSockets (for live admin tracking)

4. MODULE BREAKDOWN & DETAILED LOGIC
--------------------------------------------------------------------------------

A. ATTENDANCE & WORKING HOURS ENGINE:
   - Punch-In Workflow:
     1. User opens app -> verifies GPS permissions are active.
     2. System fetches high-accuracy GPS coordinates (Lat, Long, Accuracy).
     3. Front camera opens -> user captures real-time live selfie (no gallery upload).
     4. App sends multipart/form-data payload:
        { userId, timestamp, latitude, longitude, address, selfieImage }
     5. Server validates coordinates, saves photo to cloud storage, marks status "PRESENT".
     6. Background tracking task is initiated immediately upon punch-in.

   - Punch-Out Workflow:
     1. User triggers punch-out -> captures checkout selfie + checkout GPS.
     2. Background tracking task is stopped.
     3. Working Hours Engine computes:
        * Total Hours = (PunchOutTime - PunchInTime) - BreakMinutes
        * Flags: Late Entry (> 9:30 AM), Early Exit (< 5:30 PM), Overtime.

B. LIVE LOCATION TRACKING & DWELL TIME (TIMELINE) GENERATOR:
   - Battery-Aware Background Ping Strategy:
     * App listens to distance changes (> 25 meters) or interval ticks (every 60-90s).
     * Filter out GPS noise (accuracy > 30 meters discarded).
   - Stationary / Dwell Detection Algorithm:
     * When consecutive pings remain within a 50m radius for >= 5 minutes:
       -> Mark state as "STATIONARY".
       -> Log 'arrivedAt' timestamp.
     * When movement exceeds 50m:
       -> Mark 'leftAt' timestamp.
       -> Calculate Dwell Time = leftAt - arrivedAt (in minutes).
       -> Reverse geocode lat/lng to human-readable address (e.g. "Tech Park, Sector 4").
       -> Append to Day Timeline as a "Stationary Stop".
     * Moving state:
       -> Stored as route path coordinates (lat/lng array) to draw the polyline.
   - Day Timeline Output Format:
     * 09:15 AM - Punch In (Office / Home Base)
     * 09:15 - 09:45 AM - Travel (Distance: 8.2 km, Duration: 30 mins)
     * 09:45 - 11:15 AM - Stopped at "ABC Hospital / Client Office" (Dwell: 1h 30m)
     * 11:15 - 11:40 AM - Travel (Distance: 4.5 km)
     * 11:40 AM - 01:00 PM - Stopped at "Sunrise Pharma Distribution" (Dwell: 1h 20m)
     * ...
     * 06:10 PM - Punch Out (Office / Client Site)

C. WORK REPORTING & CLIENT VISIT SYSTEM:
   - Add Work Details:
     * Field Reps and Managers log activities linked to their client visits.
     * Form inputs: Client/Company Name, Contact Person, Meeting Purpose (Demo, Follow-up,
       Order Booking, Payment Collection), Discussion Notes, Deal Value, Next Follow-up Date.
     * Optional Attachment: Photo of client premises or signed order form.
     * One-Tap Auto Fill: App suggests current dwell location as the visit venue.
   - Admin Review & Action:
     * Statuses: Submitted -> Under Review -> Approved / Requires Correction.
     * Admin comments & feedback thread per report.

D. ADMIN DASHBOARD COMMAND CENTER:
   - Live Fleet Monitor:
     * Real-time interactive map with markers for all active employees.
     * Status indicators: Active / Moving (Green), Stationary/At Client (Amber), Offline (Gray).
   - Attendance & Photo Audit:
     * Daily tabular logs: Employee Name, Role, Punch In Time, Punch In Photo (thumbnail
       with click-to-zoom modal), Punch Out Time, Punch Out Photo, Total Working Hours.
   - Employee Day Route & Timeline Playback:
     * Select employee + select date.
     * Visual polyline path rendered on the map with milestone pins for stops.
     * Side-by-side timeline list with duration spent at each stop.
   - Work Report Review Queue:
     * Filter by date, employee, or department.
     * Review submitted visits against GPS stop times to prevent fraudulent logs.


5. DATABASE SCHEMA DESIGN
--------------------------------------------------------------------------------

TABLE users:
- id: UUID (PK)
- name: VARCHAR(100)
- email: VARCHAR(100) UNIQUE
- password_hash: VARCHAR(255)
- role: ENUM ('ADMIN', 'BUSINESS_MANAGER', 'FIELD_REPRESENTATIVE')
- phone: VARCHAR(20)
- manager_id: UUID (Self-reference FK, for Field Reps assigned to a Manager)
- is_active: BOOLEAN DEFAULT true
- created_at: TIMESTAMP

TABLE attendances:
- id: UUID (PK)
- user_id: UUID (FK -> users.id)
- date: DATE (e.g. '2026-10-30')
- punch_in_time: TIMESTAMP
- punch_in_lat: DOUBLE PRECISION
- punch_in_lng: DOUBLE PRECISION
- punch_in_address: TEXT
- punch_in_photo_url: TEXT
- punch_out_time: TIMESTAMP NULLABLE
- punch_out_lat: DOUBLE PRECISION NULLABLE
- punch_out_lng: DOUBLE PRECISION NULLABLE
- punch_out_address: TEXT NULLABLE
- punch_out_photo_url: TEXT NULLABLE
- total_working_minutes: INTEGER DEFAULT 0
- status: ENUM ('PRESENT', 'HALF_DAY', 'LATE', 'ABSENT')
- created_at: TIMESTAMP

TABLE location_pings:
- id: BIGSERIAL (PK)
- user_id: UUID (FK -> users.id)
- attendance_id: UUID (FK -> attendances.id)
- latitude: DOUBLE PRECISION
- longitude: DOUBLE PRECISION
- accuracy: FLOAT
- speed: FLOAT
- recorded_at: TIMESTAMP

TABLE timeline_stops:
- id: UUID (PK)
- user_id: UUID (FK -> users.id)
- attendance_id: UUID (FK -> attendances.id)
- location_name: VARCHAR(255)
- address: TEXT
- latitude: DOUBLE PRECISION
- longitude: DOUBLE PRECISION
- arrived_at: TIMESTAMP
- departed_at: TIMESTAMP
- dwell_minutes: INTEGER
- created_at: TIMESTAMP

TABLE work_reports:
- id: UUID (PK)
- user_id: UUID (FK -> users.id)
- attendance_id: UUID (FK -> attendances.id)
- client_name: VARCHAR(200)
- client_address: TEXT
- meeting_type: VARCHAR(50) (e.g. 'Prospecting', 'Closing', 'Support')
- notes: TEXT
- deal_value: NUMERIC(12, 2) NULLABLE
- visit_photo_url: TEXT NULLABLE
- status: ENUM ('PENDING', 'APPROVED', 'REJECTED')
- admin_remarks: TEXT NULLABLE
- submitted_at: TIMESTAMP
- reviewed_by: UUID (FK -> users.id) NULLABLE
- reviewed_at: TIMESTAMP NULLABLE


6. REST API ENDPOINTS SPECIFICATION
--------------------------------------------------------------------------------

Authentication:
- POST /api/auth/login             -> Login with email/pass, returns JWT & user profile.
- GET  /api/auth/me                -> Get current user session & permissions.

Attendance:
- POST /api/attendance/punch-in    -> Multipart: selfie image + lat/lng/address.
- POST /api/attendance/punch-out   -> Multipart: selfie image + lat/lng/address.
- GET  /api/attendance/today       -> Get current day attendance state for mobile app.
- GET  /api/attendance/history     -> Query user's attendance records with date filters.
- GET  /api/admin/attendance       -> Admin/Manager view of all employee attendances + photos.

Location & Timeline:
- POST /api/tracking/ping-batch    -> Bulk upload buffered GPS coordinates from mobile background.
- GET  /api/tracking/live          -> Admin view of all active employees' latest coordinates.
- GET  /api/tracking/timeline      -> Get stops, dwell times, and polyline route for an employee on a date.

Work Reports:
- POST /api/reports                -> Submit daily work log / client visit.
- GET  /api/reports/my-reports     -> User's own report history.
- GET  /api/admin/reports          -> Admin/Manager view of all submitted reports.
- PATCH /api/admin/reports/:id/review -> Admin approve/reject with comments.

User Management:
- GET  /api/admin/users            -> List all staff members.
- POST /api/admin/users            -> Create new employee account with assigned role.

- Deploy backend and admin portal, configure production environment variables.
